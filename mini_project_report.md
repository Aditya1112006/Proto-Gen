**3. Problem Statement**
When someone has a product idea—whether it's a CS student figuring out their final project, a non-technical founder, or a junior designer—bridging the gap between the initial concept and a tangible prototype is really hard. It usually means spending hours fighting with UI tools like Figma or trying to write boilerplates from scratch, just to see what the idea looks like. It's frustrating because the core logic and features get lost while you're busy tweaking padding and colors. Furthermore, when the requirements shift (which they always do), you have to go back and manually update every screen or component. It's a slow, tedious cycle that kills creativity right when you just want to validate if your idea makes sense. We needed a way to just talk about our idea and have it instantly transformed into a concrete, structural prototype without getting bogged down in the technical weeds.

**4. Previous Work / Literature Survey**
When we started building this, we looked at existing tools, but none really fit our specific need for rapid, iterative prototyping from scratch.
*   **v0 by Vercel / GitHub Copilot:** These are incredibly powerful for generating code and components. However, they are mostly geared toward developers who already know *what* they want to build and need help writing the actual React code. They don't help much with the initial phase of extracting requirements or structuring the entire product workflow from a simple unstructured idea.
*   **Figma AI / Uizard:** These are great for UI generation and wireframing directly from prompts. The issue is they focus heavily on the visual design aspect. They don't generate the underlying logic, user roles, or functional requirements, which are just as important when planning out a project architecture before coding.
*   **ChatGPT / Claude:** While you can use general LLMs to brainstorm, they forget context quickly over long conversations, and their output isn't structured or actionable. You get a wall of text instead of a clean, structured JSON format or directly runnable code scaffold.

**5. Proposed Solution**
We built **ProtoGen** (the AI Prototype Generator), a web application that takes natural language ideas and automatically generates structured prototypes and runnable code. We realized the key was maintaining context, so we built a custom [PromptMerger](file:///d:/Pratham/Hackathon/ai-prototype-generator/server/src/services/promptMerger.js#7-243) that saves the user's iterative prompts in a MongoDB session and cleverly deduplicates requirements. We also wrote a [FeatureExtractor](file:///d:/Pratham/Hackathon/ai-prototype-generator/server/src/services/featureExtractor.js#6-192) utility that scans the input for domain-specific keywords (like 'cart' for ecommerce) to set the context before even hitting the AI.

On the backend, an Express server orchestrates a multi-step pipeline using the Google Gemini AI. It takes our extracted features, feeds them into a heavily structured system prompt, and guarantees the output is a rigid JSON structure containing workflows, roles, and acceptance criteria via our `prototypeValidator`. Finally, the React frontend visually tracks this pipeline (detecting domain -> extracting -> generating) and presents the user with a clean, actionable prototype. When they're ready, they can click a button, and the backend generates the actual code scaffolding based on that precise, iteratively built context.

**6. Tools & Technologies Used**
*   **React (Frontend):** Used to build the interactive, single-page application and manage the complex UI states for the generation pipeline.
*   **Vite:** Used as the build tool for the React frontend because of its incredibly fast hot module replacement during development.
*   **Tailwind CSS & Lucide React:** Used to quickly style the application and add consistent iconography without writing custom CSS from scratch.
*   **Node.js & Express (Backend):** Used to create the REST API that handles prompt processing, session management, and communication with the AI.
*   **Google Gemini API (`@google/genai`):** The core LLM used to process the natural language, extract workflows, and generate the final code output.
*   **MongoDB & Mongoose:** Used to persistently store user sessions, prompt history, and the evolving list of merged requirements.
*   **PrismJS & React Simple Code Editor:** Used on the frontend to display the AI-generated code with proper syntax highlighting and allow basic editing.

**7. Impact to Society**
While it's just a mini project, the core idea behind ProtoGen actually has real-world value for democratizing software creation. For students like us, it completely removes the initial "blank canvas" paralysis when starting a new project or assignment. We can spend more time actually coding the complex logic instead of debating what pages we need.
For indie developers or small startups without dedicated product managers or designers, it drastically cuts down the time to MVP (Minimum Viable Product). They can just type out their assumptions, get a structured list of features, and immediately see a code scaffold. It empowers people with domain expertise but limited technical skills to clearly communicate and visualize their ideas, lowering the barrier to entry for building digital tools that might solve real problems in their communities.
